任务：这是音乐分析“重试兜底版”提示词。目标不是扩写，而是保证完整、可解析、可执行。

输入：
- audio_features（时长、锚点、标签）
- feature_evidence（真实音频证据，可能包含静音断点、活跃段、响度、动态范围、声道与码率）

只允许输出：
1) 一个 JSON 对象；
2) JSON 之后可追加 markdown（可选，尽量短）。

JSON 字段（必须齐全）：
{
  "title": "字符串",
  "summary": "一句话用途总结",
  "fit_genres": ["适配题材"],
  "risk_genres": ["不适配题材"],
  "sections": [
    {
      "section_no": 1,
      "label": "乐段名称",
      "start_sec": 0.0,
      "end_sec": 15.7,
      "energy_level": "低/中/高",
      "main_layers": ["低频层","中频层"],
      "instrument_guess": ["配器1","配器2"],
      "entry_suggestion": "建议进入方式",
      "exit_suggestion": "建议退出方式"
    }
  ],
  "structure_logic": {
    "pattern_guess": "AB/ABB/三幕推进/其他",
    "repeat_groups": ["A≈A1","B≈B1"],
    "progression_comment": "层次递进说明"
  },
  "hit_points": [
    {"time_sec": 83.2, "type": "峰值/转折/抽空", "usage": "动作或台词对齐建议"}
  ],
  "mix_notes": ["混音建议"],
  "key_points": ["关键摘要"],
  "markdown": "简短补充说明"
}

硬约束：
1) 禁止输出 JSON 之外的前后缀说明。
2) 所有值使用中文。
3) 不得编造不存在的时间点；时间必须来自输入证据。
4) 若信息不足，允许保守填充，但字段必须完整。
5) title 字段固定写为“音乐分析结果”，不得省略、不得改名、不得留空。
6) summary 字段必须输出一句中文用途总结，不得省略、不得留空。
7) fit_genres、risk_genres、sections、hit_points、mix_notes、key_points、structure_logic 均不得省略；若证据不足可返回空数组或保守对象，但字段必须存在。
8) 若 feature_evidence 中存在明显静音断点/活跃段变化，sections 必须体现分段差异，不得所有乐段都写成同一套“主层次/配器推测”。
9) 即便证据不足，也要尽量让不同乐段的描述有层次变化，避免整篇重复。

长度约束（严格）：
1) sections<=4，hit_points<=4。
2) fit_genres/risk_genres 各<=3。
3) mix_notes<=4，key_points<=4（单条<=24字）。
4) summary<=40字，markdown<=220字。
