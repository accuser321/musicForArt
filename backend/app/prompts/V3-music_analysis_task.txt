任务：只基于输入的 audio_features，输出可被后续“执行单生成”直接消费的音乐分析证据。

输入：
- audio_features（时长、锚点、频段/能量信息、标签）

输出目标（业务优先）：
1) 识别乐段结构与层次递进；
2) 明确可用于对位的命中点；
3) 给出创作可执行建议（不是泛化鉴赏）。

输出 JSON（必须完整）：
{
  "title": "字符串",
  "summary": "一句话用途总结",
  "fit_genres": ["适配题材"],
  "risk_genres": ["不适配题材"],
  "sections": [
    {
      "section_no": 1,
      "label": "乐段名称",
      "start_sec": 0.0,
      "end_sec": 15.7,
      "energy_level": "低/中/高",
      "main_layers": ["低频层","中频层","高频层","空间层"],
      "instrument_guess": ["配器1","配器2"],
      "entry_suggestion": "建议进入方式",
      "exit_suggestion": "建议退出方式"
    }
  ],
  "structure_logic": {
    "pattern_guess": "AB/ABB/三幕推进/其他",
    "repeat_groups": ["A≈A1","B≈B1"],
    "progression_comment": "层次递进说明"
  },
  "hit_points": [
    {
      "time_sec": 83.2,
      "type": "峰值/转折/抽空",
      "usage": "动作或台词对齐建议"
    }
  ],
  "mix_notes": ["混音建议"],
  "key_points": ["关键摘要"],
  "markdown": "完整可读分析"
}

硬约束：
1) 必须先输出 JSON，再输出 markdown。
2) 只允许使用输入证据，不得编造不存在的时间点。
3) 所有值使用中文。
4) sections/hit_points 的时间要可用于后续对位。

长度约束：
1) sections<=6，hit_points<=6。
2) key_points<=6（每条<=32字）。
3) mix_notes<=6（每条<=38字）。
4) summary<=60字，markdown 450-700字。
