# 动作分析主链路 UAT 复测清单 V1

适用范围：
- 用户端：动作提取、动作图谱推荐、动作补充单、用户投稿音效
- 运营端：问题词替代设置、元数据与赛道分配、通用元数据层、赛道特化维护区、动作补充单运营、行为审计

当前测试目标：
- 验证动作分析主链路在“空图谱起步 -> 运营维护 -> 前台推荐增强”这条完整流程下可稳定工作
- 验证用户端结果、运营端维护动作、状态流转、补库与恢复逻辑是否符合业务预期

---

## 1. 复测前提

### 1.1 当前环境前提
- 已保留用户登录数据
- 已清空：
  - 项目数据
  - 行为日志
  - 保底映射
  - 通用元数据与赛道数据
- 当前图谱状态应为：
  - 通用元数据 `0`
  - 玄幻 `0`
  - 言情 `0`
  - 悬疑 `0`
  - 科幻 `0`

### 1.2 测试建议文本
- 建议准备一段玄幻文本，包含明显动作表达，例如：
  - `结印`
  - `飞身`
  - `幻出`
  - `腾空而起`
  - `扔出去`
  - `拿出来`

这样更容易覆盖：
- 问题词替代
- 语义推荐词
- 直达音效/整体音效建议
- 通用元数据与赛道特化维护

---

## 2. 用户端主链路复测

## 2.1 创建项目

### 用户操作
1. 打开用户端首页
2. 输入项目标题
3. 选择赛道
4. 点击 `1) 创建项目`

### 期待值
- 用户视角：
  - 项目创建成功
  - 展示用户可读结果，不是 JSON
  - 创建时间显示为北京时间
- 运营视角：
  - 后台行为审计可看到 `create_project`

---

## 2.2 文本分析

### 用户操作
1. 粘贴文本
2. 点击 `2) 文本分析`

### 期待值
- 用户视角：
  - 文本分析结果正常返回
  - 今日用量正确刷新
  - 相同文本当天重复提交不重复扣字符
- 运营视角：
  - 后台行为审计可看到 `text_analysis`
  - 行为卡片可看到 LLM 摘要、调用次数、模型、耗时

---

## 2.3 动作提取

### 用户操作
1. 在已有文本基础上点击 `6) 动作提取`

### 期待值
- 用户视角：
  - 展示 `动作提取明细列表`
  - 不展示调试 JSON、Prompt 校验、分段明细等内部内容
  - 动作词识别结果与文本内容基本一致
- 运营视角：
  - 后台行为审计可看到 `action_verb_analysis`

---

## 2.4 动作图谱推荐（空系统初次测试）

### 用户操作
1. 点击 `7) 动作图谱推荐`

### 期待值
- 用户视角：
  - 能返回动作推荐结果，不应 500 或空白
  - 因为当前图谱为空，结果中可能出现较多：
    - `保底生成`
    - `系统建议扩展词 / LLM建议`
    - `系统建议音效 / LLM建议`
  - `语义推荐词` 应明显丰富，不应只剩动词本身
  - `直达音效 / 整体音效` 如无现成素材，也应能看到建议词，而不是完全空白
  - 不应展示明显无意义碎词，例如：
    - `一`
    - `而起`
    - `起`
    - `出`
    - `去`
- 运营视角：
  - 后台应收到：
    - 保底生成待办提醒
    - 对应问题词待确认项
  - 行为审计中可看到 `action_sfx_graph`

---

## 2.5 问题词替代设置

### 运营操作
1. 进入后台
2. 打开 `结构维护：保底生成与收敛`
3. 点击 `加载保底生成监控`
4. 在 `待运营确认` 中处理问题词

### 操作要点
- 上方词是：原始问题词
- 下方勾选的是：替代展示词
- 保存后的真实含义是：
  - `问题词 -> 替代展示词`
- 不是把下方词收敛到上方

### 期待值
- 运营视角：
  - 待运营确认支持分页
  - 卡片按两行三列展示
  - 保存成功后，这组词应从待确认区消失
  - 已保存规则应进入：
    - `现有问题词替代规则`
  - 释放后应回流到 `待运营确认`
- 用户视角：
  - 下次同文本再次动作图谱推荐时
  - 原始问题词不再直接展示
  - 优先展示替代词

### 重点验证例子
- `惊恐道 -> 惊恐`
- `扔出去 -> 扔出`
- `拿出来 -> 拿出`
- `引来 -> 引来`（保留原始问题词本身）

---

## 2.6 替代规则进入元数据建设候选

### 运营操作
1. 在 `结构维护：元数据与赛道分配` 中观察候选词来源

### 期待值
- 运营视角：
  - 问题词替代规则产生的展示词，会成为后续元数据建设来源
  - 但不会自动进入通用元数据或赛道特化
- 业务解释：
  - `保底生成与收敛` 负责“认词”
  - `元数据与赛道分配` 负责“建图”

---

## 2.7 通用元数据建设

### 运营操作
1. 在 `结构维护：元数据与赛道分配` 中选择 `通用元数据`
2. 通过：
   - `补入通用元数据`
   或
   - `新建通用元数据`
   打开某个词的维护节点
3. 在 `通用元数据层` 中维护：
   - 核心扩展词
   - 直达音效
   - 整体音效
4. 点击 `保存通用元数据`

### 期待值
- 运营视角：
  - 词保存后进入通用元数据下拉
  - 页面不会一直卡在 `保存中...`
- 用户视角：
  - 再次动作图谱推荐时
  - 该词应优先体现为：
    - `通用层`
    - 已维护的语义推荐词
    - 已维护的直达/整体音效

---

## 2.8 赛道特化建设

### 运营操作
1. 在 `结构维护：元数据与赛道分配` 中选择目标赛道
2. 通过：
   - `去创建赛道动词`
   或直接选中已有赛道节点
3. 在 `赛道特化维护区` 中维护：
   - 赛道扩展词
   - 直达音效
   - 整体音效
4. 点击 `保存赛道特化`

### 期待值
- 运营视角：
  - 点击 `去创建赛道动词` 后，应能进入对应赛道节点的维护流程
  - 保存成功后节点应进入赛道目录
- 用户视角：
  - 再次动作图谱推荐时
  - 当前赛道下应能看到：
    - `赛道层`
    - 更贴赛道的语义推荐词
    - 更贴赛道的直达/整体音效

---

## 2.9 语义推荐词复测

### 用户操作
1. 在完成部分通用或赛道维护后
2. 再次点击 `7) 动作图谱推荐`

### 期待值
- 用户视角：
  - `语义推荐词` 明显丰富
  - 来源说明清楚：
    - `系统建议扩展词 / LLM建议`
    - `通用层`
    - `赛道层`
  - 语义推荐词不应大面积为空
- 运营视角：
  - 后台节点页中：
    - `核心扩展词`
    - `赛道扩展词`
    可以继续接收和确认 LLM 建议

---

## 2.10 直达音效 / 整体音效复测

### 用户操作
1. 在有一定维护基础后，再次点击 `7) 动作图谱推荐`

### 期待值
- 用户视角：
  - `直达音效来源(可下载)` 不应长期为空
  - `整体音效来源(可下载)` 不应只剩动词本身
  - 若没有真实素材，至少应能看到：
    - `系统建议音效 / LLM建议`
- 运营视角：
  - 后台节点页中：
    - `直达音效`
    - `整体音效`
    候选应有 `LLM建议`

---

## 2.11 从赛道删除与恢复

### 运营操作
1. 在赛道节点中对某词执行从赛道删除
2. 检查 `赛道删除池`
3. 如有需要，再点击恢复

### 期待值
- 运营视角：
  - 删除后，该词应进入 `赛道删除池`
  - 后续可恢复到当前赛道
- 用户视角：
  - 删除后，该赛道的推荐不再借用这条数据
  - 恢复后推荐重新出现

---

## 2.12 赛道特化移空保存

### 运营操作
1. 打开如 `玄幻::躲闪`
2. 在 `赛道特化维护区` 中把词移除
3. 点击 `保存赛道特化`

### 期待值
- 运营视角：
  - 这条数据应进入 `赛道删除池`
  - 可以后续恢复
- 用户视角：
  - 当前赛道下这条特化不再继续生效

---

## 2.13 动作补充单主链路

### 用户操作
1. 在动作图谱推荐后，点击动作补充单相关入口

### 期待值
- 用户视角：
  - 表格只展示：
    - 动作词
    - 目标版本
    - 关联语义
    - 待补充音效词
  - 底部应有明确提示：
    - 补充单已提交系统，后续会通知
- 运营视角：
  - 后台 `动作补充单运营` 状态流转正常：
    - 待合并
    - 部分补齐
    - 已补齐待通知
    - 已通知
  - 行为审计可看到相关日志

---

## 2.14 用户投稿更合适音效

### 用户操作
1. 在动作图谱推荐里打开 `上传更合适音效`
2. 上传用户自己已有的更优音效

### 期待值
- 用户视角：
  - 投稿入口默认收起
  - 点击后展开
  - 投稿成功后可在用户中心看到状态
- 运营视角：
  - 后台可审核投稿
  - 审核通过后给予下载额度奖励
  - 不合适的投稿可驳回/删除

---

## 2.15 运营行为审计

### 运营操作
1. 进入后台 `运营行为审计`
2. 点击 `查询行为日志`

### 期待值
- 运营视角：
  - 可看到行为时间线
  - 每条行为卡片包含：
    - 总耗时
    - 调用次数
    - 使用模型
  - 展开详情后可看到：
    - 每次 LLM 调用耗时
    - 每次 LLM 调用状态
    - 每次调用对应提示词

---

## 3. 关键判定标准

若以下 6 条都成立，可判断动作分析主链路具备上线前复测价值：

1. 用户端动作提取结果稳定，不再暴露内部调试内容  
2. 动作图谱推荐在空系统和已维护系统下都能正常返回  
3. 保底生成可被运营处理，并在下一次推荐中转化为更合理展示词  
4. 通用元数据与赛道特化维护能真实影响用户端推荐结果  
5. 语义推荐词、直达音效、整体音效已具备 LLM 建议能力  
6. 动作补充单、用户投稿音效、运营行为审计三条辅助链路正常工作

---

## 4. 当前已知复测关注点

1. `动作图谱推荐` 仍依赖 LLM 建议，需继续观察等待时长是否可接受  
2. `直达音效 / 整体音效` 当前虽已接入 LLM 建议，但仍需观察实际命中质量  
3. `去创建赛道动词`、`保存赛道特化`、`赛道删除池` 这几条链曾是高风险 bug 点，复测时要重点回归  
4. 在空图谱起步阶段，第一次推荐中保底生成较多属于正常现象；重点看运营处理后第二次推荐是否改善

---

## 5. 推荐复测顺序

建议按这条顺序完整走一遍：

1. 创建项目  
2. 文本分析  
3. 动作提取  
4. 动作图谱推荐（第一次，观察保底生成）  
5. 后台处理问题词替代  
6. 后台补入通用元数据 / 新建赛道动词  
7. 维护核心扩展词 / 赛道扩展词 / 直达音效 / 整体音效  
8. 动作图谱推荐（第二次，观察推荐是否改善）  
9. 动作补充单  
10. 用户投稿音效  
11. 运营行为审计复核整条链
