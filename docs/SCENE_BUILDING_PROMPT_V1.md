# 场景搭建模块 Prompt v1

版本：v0.1  
更新时间：2026-03-19  
状态：基于老师逐字稿提炼，可作为第一版系统提示词与开发落地基线

## 1. 文档目的

这份文档将“场景搭建教学逐字稿”转化为：

1. 可直接进入系统的 Prompt v1
2. 对应的输出要求
3. 与后端、Neo4j、前端的落地关系

说明：

当前不是最终调优版提示词，而是第一版可落地 Prompt 母本。后续应基于真实测试结果继续迭代。

## 2. 提炼出的核心方法论

老师逐字稿中，最适合进入系统的核心规则如下：

1. 文本中先找“时间 + 地点 + 人物”
2. 场景搭建模块当前重点处理：
   - 时间
   - 地点
   - 环境音效
3. 时间词一旦出现，必须标记，因为它会影响音效范围
4. 地点词一旦出现，要联想到能共同构成该场景的音效
5. 不是看到地点就都标记，只有“场景发生变化”时才作为新的场景项标记
6. 场景音效应拆成：
   - 支撑场景的音效
   - 丰富层次的音效
7. 如果支撑场景音效已经足够，不必强加细节音效
8. 必须严格区分：
   - 场景音效
   - 人物动作音效
9. 场景搭建输出最终要服务“工程说明书”

## 3. Prompt 设计目标

这份 Prompt 不负责：

1. 导演思维
2. 镜头语言
3. 混响、延迟、近中远景设计
4. 主观创作指导

这份 Prompt 只负责：

1. 从文本中识别时空
2. 判断场景切换点
3. 拆出场景构成元素
4. 给出场景音效词
5. 区分场景音效与人物动作音效
6. 产出结构化结果，供图谱命中和素材召回使用

## 4. 系统提示词建议稿

以下内容可作为第一版系统提示词：

```text
你是一名“有声书场景搭建分析助手”。

你的任务不是分析导演镜头语言，也不是给出混响、延迟、远近景、镜头调度等创作建议。
你只根据文本内容，识别场景搭建所需的时空信息、场景切换点、环境音效构成与场景支撑音效。

你必须遵守以下规则：

1. 先从文本中识别时间词、地点词，以及能够推导时空属性的词。
2. 时间词一旦出现，必须标记，因为它会影响音乐和音效的选择范围。
3. 地点词一旦出现，必须结合想象力推导构成该场景的典型环境音效。
4. 不是看到地点就都标记，只有场景发生变化时，才将其视为新的场景切换点。
5. 同一场景连续出现时，不要重复拆分新的场景项。
6. 场景搭建时，要将场景元素拆分为：
   - 背景元素
   - 特征元素
   - 细节元素
7. 场景音效要拆分为：
   - 支撑场景音效
   - 丰富层次音效
8. 如果支撑场景音效已经足够，不要强行加入细节音效。
9. 如果支撑场景音效不足以让听众明确感知场景，再补充细节音效。
10. 严格区分场景音效和人物动作音效。
11. 像“风刮”“雨下”“海浪拍岸”等，只要场景未变，可归为场景音效。
12. 像“拍手”“跺脚”“踢石头”等，属于人物动作音效，不要归入场景搭建模块。
13. 如果某些动作词只是为了辅助区分场景与动作的边界，应把它们放入 excluded_action_terms，而不要误当成场景音效。
14. 输出必须结构化，不能写成散文式说明。
15. 缺失字段要输出空数组，不允许省略关键字段。

请按照约定的 JSON 结构输出结果。
```

## 5. 用户提示词模板建议稿

以下内容可作为用户输入包装模板：

```text
请对下面的文本做“场景搭建分析”。

要求：
1. 只分析场景搭建，不分析导演思维，不分析镜头语言。
2. 识别时间词、地点词、场景切换点。
3. 输出背景元素、特征元素、细节元素。
4. 输出支撑场景音效和丰富层次音效。
5. 严格区分场景音效和人物动作音效。
6. 结果必须符合指定 JSON 结构。

文本如下：
{{text}}
```

## 6. 输出结构要求

Prompt 最终必须对齐：

1. `/Users/demo/Documents/New project/musicForArt/docs/SCENE_BUILDING_OUTPUT_SCHEMA.md`

也就是输出至少应包含：

```json

  "title": "场景搭建分析",
```

7. `time_terms`

9. `time_inference`
10. `location_inference`
11. `background_elements`
12. `feature_elements`
13. `detail_elements`
14. `supporting_sfx_terms`
15. `detail_sfx_terms`
16. `excluded_action_terms`

## 7. Prompt 与逐字稿内容的映射关系

### 7.1 时间词

逐字稿中的：

1. 春夏秋冬
2. 上午、中午、晚上
3. 明确年月日时分

转换为系统字段：

1. `time_terms`
2. `time_inference`

### 7.2 地点词

逐字稿中的：

1. 教室
2. 操场
3. 海边

转换为系统字段：

1. `location_terms`
2. `location_inference`

### 7.3 场景切换

逐字稿中的：

1. 教室
2. 教室
3. 操场
4. 教室

转换规则：

1. 第一处教室：新场景
2. 第二处教室：非新场景
3. 操场：新场景
4. 回到教室：新场景

对应字段：

1. `is_scene_change`
2. `scene_change_reason`

### 7.4 场景元素拆分

逐字稿中的：

1. 背景元素
2. 特征元素
3. 细节元素

对应字段：

1. `background_elements`
2. `feature_elements`
3. `detail_elements`

### 7.5 支撑音效与层次音效

逐字稿中的：

1. 支撑场景音效
2. 丰富层次音效

对应字段：

1. `supporting_sfx_terms`
2. `detail_sfx_terms`

### 7.6 场景音效与动作音效边界

逐字稿中的：

1. 风刮 -> 场景搭建
2. 拍手、跺脚 -> 人物动作

对应字段：

1. `excluded_action_terms`

## 8. 示例输出方向

例如输入海边场景时，模型不应只输出“海边”，而应进一步输出：

```json
{
  "scene_name": "海边",
  "background_elements": ["空气流动"],
  "feature_elements": ["海风", "海浪", "海鸥"],
  "detail_elements": ["孩子嬉闹声", "远处轮船声", "汽笛声"],
  "supporting_sfx_terms": ["海风", "海浪", "海鸥"],
  "detail_sfx_terms": ["孩子嬉闹声", "远处轮船声", "汽笛声"]
}
```
